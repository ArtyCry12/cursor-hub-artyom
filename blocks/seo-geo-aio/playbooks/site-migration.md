# Playbook: Миграция сайта без потери SEO-трафика

Источник: кейс Rush Agency (транскрипт WLeS6ixH-mM, кейс BTX-завода: 283 → 3000 визитов за 4 месяца, ноль дней провала индексации). Нормализовано 2026-09-17.

**Когда применять:** пересборка сайта (в т.ч. через `clone-website` маршрут), переезд CMS, редизайн с сменой URL-структуры.

**Контекст:** страх миграции оправдан — известны проекты, терявшие 50% трафика на год+. Цель миграции не «сделать аккуратно», а «у поисковика не осталось ни одного вопроса о том, что случилось с сайтом».

## 7 шагов (строгий порядок)

1. **Полная копия старого сайта до любых работ.** Выгрузить с хостинга целиком (файлы + БД + контент). Страховка от потери уникального контента/фото, существующих только на старом хостинге. Работать локально с копией.

2. **Структура контента проектируется ДО вёрстки** (не наоборот). Структура блоков страницы = ТЗ на дизайн. Семантика раскладывается на страницы так, чтобы страницы не каннибализировали друг друга. Универсальной схемы нет: структура = f(семантика, ассортимент, ниша).

3. **Карта соответствия адресов (redirect map).** Каждый старый URL → новый URL по смыслу. Нет страницы-приёмника → ближайшая по смыслу страница. **Ни в коем случае не свалка редиректов на главную** — самая частая и дорогая ошибка миграций. Формат: CSV/таблица `old_url,new_url,status`.

4. **Контент переносится адаптированным, не as-is.** Новая структура карточек (вкладки: описание/характеристики/применение/FAQ) → старый текст раскладывается по вкладкам, а не сваливается в description.

5. **Техдолг закрывается одновременно с миграцией**, не «потом»: зеркала (301, www/https склейка), метатеги (уникальные на каждой странице), robots.txt (открытые JS/CSS; **проверить, что не заблокированы AI-боты** — см. SKILL Workflow 2), sitemap, Core Web Vitals. Один раз исправили — один раз поиск пересчитал.

6. **Мониторинг первых дней — индексация, не трафик.** Трафик реагирует позже и пугает зря. Смотреть: Search Console/Вебмастер (страниц в индексе, всплески ошибок, коды ответа сервера). Проблема видна на 2-й день, не через месяц по упавшим заявкам.

7. **Не переезжать в свой сезон.** Миграция до пикового сезона; ошибка в пик = годовая выручка.

## Ошибки-индикаторы старого сайта (из кейса)

Проверять до переезда (в кейсе: 31% оптимизации при норме 85%):
- Одинаковые H1 на десятках страниц → «выберет одну, остальные выкинет»
- Зеркала не склеены (www / http / https = 4 сайта-близнеца для робота)
- robots.txt закрывает JS/CSS → робот видит страницу без оформления
- Быстрая проверка зеркал: открыть сайт с www и без — если адрес не переключается, склейки нет (чинится за 15 минут)

## Динамическая генерация страниц (если применимо)

Страницы-ланды под комбинации свойств товаров (фасадная краска × бетон × наружные работы) генерируются **только под реальный спрос**: сначала собрать запросы и объёмы, открывать страницу только там, где есть спрос. Генерация «всё подряд» → тысячи пустых однотипных страниц → пессимизация всего сайта. Кейс: 43 товара → сотни живых страниц.

## Техничка нового сайта (минимум)

- Мобильная версия · склейка зеркал 301 · уникальные title/description · открытые CSS/JS · Core Web Vitals
- Микроразметка: Product/Organization (цена, бренд), Article+даты+автор на блоге, Breadcrumbs, FAQPage (валидна; rich results убраны — ценность в Q&A)
- **llms.txt — не ждать эффекта** (см. references/ai-search-2026.md §5); опционально для IDE-агентов
